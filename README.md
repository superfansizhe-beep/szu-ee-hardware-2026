> 目标：不接任何硬件，在 Mac 上用 **Renode 全仿真 STM32F407**，把笔试 10 道题全部做出来并亲眼验证；
> 逻辑全部按真板写，只有"读传感器 / 驱动执行器"这层在仿真里用 **SRAM mailbox（数字孪生）** 顶替。

---

## ⚠ 必读：仿真保真边界（仿真成功 ≠ 硬件成功）

Renode 是**指令级模拟器**，擅长验证**数字逻辑、状态机、通信协议**；它**不模拟**
时钟门控、模拟量、电气特性和精确时序。务必清楚下面的边界，别把"仿真能跑"当成"真板能跑"。

| 仿真不模拟 / 简化 | 我们这套的实际情况 | 上硬件必须做的事 |
|---|---|---|
| **时钟门控**（真板不开 RCC、外设不工作；Renode 不强制） | 用到真外设的 **00a/00b/q01/q02/q04/q06/q09/q10 都已写 RCC 开时钟**；q03/05/07/08 走 mailbox、没配外设 | mailbox 题补 GPIO/定时器/ADC 初始化并开 RCC |
| **精确周期/延时**（`delay` 是虚拟时间，真板取决于主频/缓存） | 忙等 `delay`：00a/q01/q02/q05/q07；绑 SysTick：q06/q08/q09/q10 | 精确时序用定时器 + 示波器核对，别数指令 |
| **模拟量**（ADC/DAC/比较器多为缺失或固定值） | q06 红外、q08 光控的感应值由**脚本喂入** | q08 用 ADC 采样；q06 可用数字模块(DO) |
| **中断延迟**（真板入口有 12~16 周期 + 上下文保存；Renode 即时） | q02 EXTI、q06/08/09 SysTick | 慢应用无影响；高实时/优先级反转靠硬件验证 |
| **DMA**（不少 DMA 仅 stub） | **本套未用 DMA**，全轮询 | 将来用 DMA 搬数据需硬件验证 |
| **电气特性**（驱动能力、上下拉、阈值、噪声、RC 时间常数全理想） | LED 亮度、按键消抖均理想化；按键用**软件消抖** | 驱动能力/上下拉/噪声上硬件确认 |
| **外设覆盖不均**（GPIO/UART/SPI/定时器较成熟；ADC/QSPI/USB/CAN 等弱） | 本套主要用 GPIO/UART/定时器/SysTick；**q03 是"虚拟显示"，并非真 I2C 驱动 SSD1306** | q03 补 I2C 时序 + SSD1306 初始化/取模刷屏 |

**一句话**：控制逻辑（状态机、扫描、防抖、命令解析、角度→脉宽映射）在仿真里**全真、可信**；
凡是涉及"模拟电压、真实物理响应、精确到周期的时序、屏幕/传感器底层协议"，**以真板为准**。
验收讲解时主动说清这条边界，反而是加分项——说明你知道仿真在验证什么、不在验证什么。

## 一、考核是怎么考的（务必先读）

- **线下集体验收，当面烧真板 + 讲解**。题目要求"当面进行烧写程序并解释代码和注释含义"。
  所以**仿真是学习/调试手段，验收那天要在真硬件上烧**。本套工程逻辑全真，迁移成本只在电气层。
- **注释 = 自己的见解，是防抄袭核心**。老师会照着注释问"为什么这么写"，答不上=不是自己的。
  注释写得好才有满分。→ 注释要写**为什么**（为什么开时钟、为什么要等、状态机怎么想的），不要只复述代码。
- **做了提高题有优待**：基础题现场只抽几道、重点展示提高题；只做基础题则每道都要展示。
- **排名多维度**：完成数量、完成效果、理解程度。总分 100 封顶（基础 95 + 附加 30）。
- 可查资料/借鉴例程，**不许抄同学**；有项目经验可向部长申请免试。

## 二·B、两层结构：仿真版 vs 真板版（验收要烧的是这一层）

> **每个工程现在有两份固件。仿真版 `main.c` 一个字节都没动过**，验收当天烧的是 `main_board.c`。

| | 仿真版 | 真板版 |
|---|---|---|
| 源文件 | `main.c` | `main_board.c` |
| 构建 | `bash build.sh` | `bash build_board.sh` |
| 去哪跑 | Renode（全仿真） | STM32F407 实板 + ST-Link 烧录 |
| 传感器/执行器 | SRAM mailbox 打桩 | **真实 ADC / 定时器 / GPIO** |
| 应用逻辑 | —— | **和仿真版一致，只换 IO 层** |

**为什么要两层**：考核要求「当面烧写程序并解释代码」。仿真版已经把状态机、
消抖、命令解析、角度→脉宽这些**逻辑**在 PC 上验证过了；真板版把这套逻辑原封不动
接到真实外设上。上板只需要看 `main_board.c` 顶部的**引脚表**，改接线只改那一处。

**共用一个公共驱动层** `stm32f4_common.h`（每个工程目录下都有一份逐字节相同的副本，
这样单独拷走任意文件夹也能编译）：

- 时钟：HSE 8MHz → PLL 168MHz，**HSI 自动兜底**（晶振没起振也能跑，不会黑屏）
- GPIO / TIM PWM / USART / ADC / I2C / EXTI / TIM6 毫秒时基
- 完整 98 项中断向量表（弱符号，用不到的中断自动落到默认处理）
- **每个基址和位掩码都对照过 ST 官方 CMSIS 头文件 + Renode 平台定义**，不凭记忆写
- 文件末尾有「勘误」小节，列了 7 条凭记忆写必踩的坑 —— 讲解时是很好的素材

```bash
# 编译真板版（产物 .hex 给 ST-Link Utility / STM32CubeProgrammer）
cd q08_光控夜灯
PATH="/opt/homebrew/bin:$PATH" bash build_board.sh
```

### 统一引脚表（USART1 所有题通用作调试/上报）

```
PA9  = USART1_TX (AF7) ── USB-TTL 的 RXD      115200-8-N-1
PA10 = USART1_RX (AF7) ── USB-TTL 的 TXD
```

| 题 | 关键引脚 |
|---|---|
| Q1 点灯大师 | LED 红/绿/蓝 = PA0/PA1/PA2；按键 A=PB0、B=PB1（上拉、低有效） |
| Q2 流水灯 | LED1~4 = PD12~PD15(TIM4_CH1~4)；按键1=PB0(EXTI0)、按键2=PB1(EXTI1) |
| Q3 OLED | I2C1：PB6=SCL、PB7=SDA；SSD1306 128x64，地址 0x3C |
| Q4 电机风扇 | PWMA=PA0(TIM2_CH1)、AIN1=PA1、AIN2=PA2、STBY=PA3；按键=PB0/PB1 |
| Q5 舵机 | SG90=PB6(TIM4_CH1)；电位器 ADC=PA0(ADC1_IN0) |
| Q6 红外避障 | 红外DO=PB0、红外AO=PA1(ADC1_IN1)；有源蜂鸣器=PB6；LED红=PB1、绿=PB2 |
| Q7 空气竖琴 | HC-SR04 TRIG=PB6、ECHO=PB7；无源蜂鸣器=PB9(TIM4_CH4) |
| Q8 光控夜灯 | 光敏 ADC=PA0(ADC1_IN0)；LED PWM=PA6(TIM3_CH1) |
| Q9 串口控制 | LED PWM=PA0(TIM2_CH1)；USART1 PA9/PA10 |
| Q10 雷达建图 | SG90=PB6(TIM4_CH1)；HC-SR04 TRIG=PB7、ECHO=PB8；提示LED=PB0 |

> ⚠ 三个必须注意的硬件约束：
> ① **HC-SR04 的 ECHO 是 5V**，必须分压到 3.3V 以内再接 STM32（代码里用的是 1k/1k 分到 1/2 ≈ 2.5V，
>    够过 VIH 门限；题目常见的 1k/2k 分到 1.67V **低于** 2.31V 门限，不可靠）。
> ② **红外 AO 输出可能超 3.3V**，接 ADC1_IN1 前要分压。
> ③ 串口调试务必**共地**，否则能收不能发。

## 四、通用流程（每个工程都一样）

```bash
cd 某工程目录

# 1) 编译：生成 *.elf（含调试符号/段布局）、*.bin（纯二进制）、*.hex
PATH="/opt/homebrew/bin:$PATH" bash build.sh

# 2) 仿真验证：观察手自动启动 Renode、加载 ELF、模拟输入、读结果
/opt/homebrew/bin/python3.12 watch_xxx.py
```

**从 C 到芯片跑起来，中间发生了什么：**
1. `arm-none-eabi-gcc` 把 `main.c` 编译成 Cortex-M4 的机器码（`main.o`）；
2. 链接器按 `stm32f407.ld` 把各段摆到固定地址：
   Flash `0x08000000`（向量表+代码）、RAM `0x20000000`（数据）；
3. Renode 加载 `.elf`，把虚拟 CPU 的 PC 指向复位入口，开始跑；
4. `watch_*.py` 通过 monitor 注入输入、推进虚拟时间、读 RAM/串口来验证。

**几个文件类型**
- `.ld`：链接脚本，规定代码/数据放哪个地址、栈在哪；
- `.elf`：最终可执行文件，带段信息和符号（Renode/GDB 用它）；
- `.bin/.hex`：ELF 的纯二进制/带地址格式，烧真板常用；
- mailbox：固定在 SRAM 顶端的几个共享 32 位格子，固件和 Python 用它对话。

## 五、十道题速查

| 题 | 外设 | 关键技能 | 仿真里传感器/执行器怎么打桩 | 真板要改的地方 |
|---|---|---|---|---|
| Q1 点灯大师 | 三色LED + 2按键 | 状态机、沿检测、非阻塞 | 按键 `gpioPortA OnGPIO`，读 ODR 验灯色 | — |
| Q2 流水灯 | 4 LED + 2按键 | **外部中断 EXTI** | 按键必须 `sysbus.exti OnGPIO <line>` 才触发中断 | — |
| Q3 OLED | SSD1306 OLED | I2C、帧缓冲、字库 | 4行文字写 SRAM，Python 渲染 `oled_screen.png` | 接 I2C + 字库取模，刷屏 |
| Q4 电机风扇 | TB6612 + 直流电机 + 2按键 | GPIO 方向 + PWM 调速 | AIN1/AIN2/STBY 用 GPIOE，占空比写 mailbox | 占空比改定时器 CCR |
| Q5 舵机 | SG90 + 电位器 | **PWM、角度→脉宽** | 目标角度写 SRAM（替电位器/ADC），脉宽写 SRAM | 读 ADC、写 TIM CCR |
| Q6 红外避障 | 反射红外 + 有源蜂鸣器 + 红/绿灯 | ADC、阈值、非阻塞分级 | AO 强度写 SRAM，比较器阈值判定，节奏分级 | AO 改读 ADC |
| Q7 空气竖琴 | HC-SR04 + **无源蜂鸣器** | 测距分区、频率=音高 | 距离写 SRAM，频率写 SRAM | 频率改定时器 PWM |
| Q8 光控夜灯 | 光敏电阻 + LED | ADC + PWM、防抖、平滑 | 亮度写 SRAM，占空比写 SRAM | 亮度读 ADC、占空比写 CCR |
| Q9 串口控制 | UART + LED | SysTick、串口收发、命令解析 | `uart4 WriteLine` 喂命令，抓回复 | — |
| Q10 雷达建图 | SG90 + HC-SR04 + UART | 全部综合 + 上位机建图 | 距离写 SRAM、脉宽写 SRAM、magic 校验 | 同 Q5/Q7 |

**关键数值约定**
- Flash `0x08000000`；RAM `0x20000000`。
- 标准工程 mailbox 多在 `0x2001FF00 / 0x2001FF04`（128K RAM 顶端）。
- Q10 把 RAM 截到 `0x3FFF0`，mailbox 在 `0x2003FFF0(距离)/F4(脉宽)/F8(magic)`。
- 有源蜂鸣器=给电平就响；无源蜂鸣器=必须给一定频率方波。
- SG90：脉宽 500µs@0°、1500µs@90°、2500µs@180°，公式 `500 + deg*2000/180`。

## 六、核心方法论：为什么要这样学

> **在 PC 上把逻辑 100% 调对，硬件只留最薄一层。**

- 固件的状态机、扫描、串口、防抖、渐变等**逻辑全部是真的**；
- 只有"读传感器（ADC/测距）"和"驱动执行器（PWM/舵机）"在仿真里换成 mailbox；
- 好处：不依赖硬件就能反复验证、可脚本化、不会烧板子；上真板只换接头。

**一个重要的时序思想**：喂数/采样必须比"状态变化"快。
- Q10 固件每 200ms 换一个角度，Python 时间片取 0.19s（<0.2s），保证每个角度窗口内喂对距离；
- Q6 最近档蜂鸣器高电平 75ms，观察脚本采样取 30ms（<75ms），才不会漏脉冲。
