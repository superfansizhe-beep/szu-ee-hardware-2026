# Q10 雷达建图（刁难：基础 5 + 附加 15 · 终章）

**一句话**：舵机带超声波 0°→180°→0° 往复扫描，每角度测距，串口发"角度:距离"，电脑画雷达图。

## 引脚 / 接线速查

| 功能 | 真板引脚 |
|---|---|
| SG90 信号 | **PB6**（TIM4_CH1） |
| HC-SR04 TRIG | **PB7** |
| HC-SR04 ECHO | **PB8** ⚠️5V 需分压 |
| 提示 LED | **PB0** |
| 串口 | PA9=TX / PA10=RX（AF7, 115200） |

> 仿真版 mailbox：`0x2003FFF0` 距离(脚本写) / `F4` 脉宽(固件写) / `F8` magic='TWIN'。

## 核心逻辑伪代码

```
scan_step(angle):
    servo_set(angle)                  # CCR = 500 + angle*2000/180
    delay_ms(200)                     # 等舵机到位 + 固定扫描节奏
    mm = hcsr04_read_mm()             # 真板: ECHO高电平µs / 58
    uart: angle ':' (mm/10) '.' (mm%10) '\r\n'      # 45:67.0
    if angle % 90 == 0:               # 关键角 0/90/180
        uart: "[LED] angle=" angle "\r\n"
        LED 闪 50ms

main():
    循环:
      for dir in {0, 1}:              # 0=去程 1=回程
        a   = dir ? 180 : 0
        step = dir ? -5 : +5          # int32_t！无符号会回绕成巨大正数
        循环: scan_step(a); if a==(dir?0:180) break; a += step
```

## 关键常量

| 项 | 值 |
|---|---|
| 步进 / 节奏 | **5°/步，200ms/步** |
| 舵机脉宽 | `500 + deg*2000/180`（500~2500µs） |
| 单程 | 0~180 共 **37 个点 ≈ 7.4s**；往返 ≈ 15s |
| 测距换算 | `距离cm = ECHO高电平µs / 58` |
| 关键角 | 0 / 90 / 180（`angle % 90 == 0`） |

## 高频追问 + 一句话答法

- **整体怎么做的？** → 三层：STM32 只做扫描和发送；串口一行一个数据点 `角度:距离`；电脑按行解析成数据点，用**极坐标**画成雷达图。STM32 不存任何数据。
- **为什么用极坐标画图？** → 雷达扫描天然是极坐标的：角度=极角，距离=半径。近的点围成一圈就是周围轮廓，一眼看出障碍物分布。直角坐标反而要自己换算。
- **怎么保证距离对应正确角度？** → 每转到角度**先等 200ms 再测**。舵机是机械结构需要时间，200ms 对应 5°，按 60°/0.1s 的转速远远够。
- **⚠️ 题目要求"转动过程中实时测"，你这样算实时吗？** → 严格说不是。这是物理限制：转动中模块也在动，测到的距离角度不准，且 HC-SR04 要求两次测量间隔 ≥60ms。我的选择是**数据准确性优先**。
- **正前方没障碍怎么办？** → ECHO 一直是低，必须设**超时**判为无效（输出 0 或 999），上位机看到无效就不画点。真板不加超时会死等。
- **为什么要发 LED 提示？** → 题目基础要求第 4 条。转到关键角额外发一行标记 + 闪 LED，这样 180° 也提示了，能看出往回扫开始。
- **图准吗？** → 三个误差源：舵机**回差**（同角度实际停位差零点几度，小角度影响大）、超声波**扩散角约 15°**（斜测会测到旁边的）、温度影响声速。近距离准，远距离误差明显。

## 被问住就说

> ⚠️ 仿真版**没有真测距**：距离是脚本喂的、脉宽是写出去的，验证的是**扫描往复逻辑和数据格式**。
> ⚠️ **建图是电脑上的 Python 脚本画的**（题目明确允许 python 处理数据绘制）。但**验收前必须确认那台电脑装了 matplotlib**，别现场翻车。
