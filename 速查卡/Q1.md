# Q1 点灯大师（10 分）

**一句话**：A 键按下点亮红灯，B 键按下三色循环闪烁，再按 A 键熄灭。

## 引脚 / 接线速查

| 功能 | 真板引脚 | 仿真版 |
|---|---|---|
| LED 红 | PA0 | PD14 |
| LED 绿 | PA1 | PD12 |
| LED 蓝 | PA2 | PD15 |
| 按键 A | PB0（上拉、**低有效**） | PA0（高有效） |
| 按键 B | PB1（上拉、**低有效**） | PA1（高有效） |

> 真板低有效 → 沿判断是"高→低"；仿真高有效 → "低→高"。被问到就说明引脚表按验收板定过。

## 核心逻辑伪代码

```
状态: OFF(全灭) / RED(红常亮) / CYCLE(三色循环)
开机 = OFF

循环:
    a,b = 读按键电平
    a_press = a && !prev_a      # 先算边沿
    b_press = b && !prev_b
    prev_a = a;  prev_b = b     # 再更新（顺序反了就废了）

    switch(state):
      OFF:   if a_press -> state=RED, 亮红
      RED:   if a_press -> state=OFF, 全灭
             elif b_press -> state=CYCLE, cycle_idx=0, 亮红
      CYCLE: if a_press -> state=OFF, 全灭
             else:  cycle_ticks++
                   if cycle_ticks >= 8: cycle_idx=(cycle_idx+1)%3, 换色, ticks=0
    delay(~25ms)
```

## 关键常量

| 常量 | 值 | 含义 |
|---|---|---|
| 换色周期 | 8 采样 × 25ms ≈ **200ms/色** | 不阻塞计数 |
| 状态数 | 3 | OFF / RED / CYCLE |
| ALL_OFF | 三个灯的"复位位"拼一起 | 一条指令全灭 |

## 高频追问 + 一句话答法

- **为什么用状态机不用 if-else？** → 因为灯显示什么取决于之前按过什么，状态机把"历史"显式存下来，改一个转移条件不动其它地方。
- **按住不放会不会重复触发？** → 不会，沿检测只认"上一圈松开、这一圈按下"，必须先算边���再更新 prev，顺序反了就失效。
- **怎么消抖的？** → 25ms 采样间隔天然跨过机械弹跳窗口，加上沿检测，两者一个管"按几次"一个管"什么时候算按下"。
- **为什么用 BSRR 不用 ODR？** → BSRR 是一条指令、不用读、天然原子、不会误伤别的脚；ODR 是读-改-写，中间被打断会出事。
- **三个灯怎么保证只亮一个？** → 先写 ALL_OFF 全灭，再写要亮那位的置位位；BSRR 写 0 的位不动，所以两步互不干扰。
