# Q8 光控夜灯（基础 10 + 附加 5 · 三条附加）

**一句话**：光敏控 LED 亮度，越暗越亮；附加要求差别明显 + 防抖 + 平滑渐变。

## 引脚 / 接线速查

| 功能 | 真板引脚 |
|---|---|
| 光敏分压点 | **PA0**（ADC1_IN0）⚠️别超 3.3V |
| LED 调光 | **PA6**（TIM3_CH1, AF2） |
| 调试串口 | PA9=TX / PA10=RX（AF7, 115200） |

> 仿真版：亮度喂进 0x2001FF00（0~4095），占空比写回 0x2001FF04（0~1000）。

## 核心逻辑伪代码

```
light_to_duty(l): return (4095 - l) * 950 / 4095    # 反向 + 留5%余量

循环:
    light = adc_read_avg(PA0, 16)                   # ①取平均
    want  = light_to_duty(light)

    diff = |want - pending|                        # ②防抖：管"什么时候认"
    if diff > BAND:  pending = want; since = millis()      # 变了→重新计时
    elif millis() - since >= STABLE_MS: stable = pending   # 稳够了→采纳

    if millis() - last_ramp >= RAMP_MS:             # ③平滑：管"怎么走到位"
        last_ramp = millis()
        cur += min(RAMP_STEP, stable - cur)         # 限速斜坡，必收敛不越过
        pwm_set_permyriad(TIM3, 1, cur)
```

## 关键常量

| 项 | 值 |
|---|---|
| STABLE_MS | **400**（要连续稳定多久才采纳） |
| BAND | **60**（差 ≤60 算"没变"） |
| RAMP_MS / RAMP_STEP | **10** ms / **25**（满量程 1000 → 约 0.4s 走完） |
| PWM 周期 | 2000µs = **500Hz**（>人眼频闪临界 100Hz） |
| ADC_AVG | 16 |

## 高频追问 + 一句话答法

- **⚠️ 防抖和平滑为什么必须拆开？** → 防抖管"什么时候认"，平滑管"怎么走到位"。只防抖不平滑 → 灯一顿一顿跳；只平滑不防抖 → 人走过灯也晃。拆开才有"人走过去灯不为所动，天真的黑了才慢慢亮"。
- **怎么做到"短暂变化不响应"？** → 差值超 BAND 就换 pending 并**重新计时**，差不大就继续等，连续满 400ms 才采纳。短暂变化会反复重置计时器，永远凑不满，所以不响应。
- **怎么做到平滑渐变？** → 限速斜坡：每 10ms 挪最多 25。写法 `差>步?步:差` 保证**一定收敛且不会越过目标**，不会来回抖。
- **映射为什么反向？** → 光敏分压是"越亮读数越大"，但灯要"越暗越亮"，所以用 4095−light。写 4095−light 而不是 1000−light 是为了**避免无符号下溢**。
- **为什么留 5% 余量？** → 免得极暗时顶到 1000、极亮时压到 0，验收时老师分不清是"到顶"还是"灯坏了"。
- **PWM 频率多少？** → 500Hz。太低有肉眼可见频闪，太高会啸叫且功耗上升。

## 被问住就说

> ⚠️ 仿真版**没有真 ADC**，亮度是脚本喂的，验证的是**防抖和平滑两个算法本身**；IO 层是打桩的。
> ⚠️ **400/60/10/25 是我定的一组经验值，没有严格标定**。被问到就说"我根据实际观察调的，不合理可以现场改参数"。
