# Q9 串口控制（基础 10 + 附加 5）

**一句话**：串口收 `SETLED:X`(0-255) 和 `FLASH:X`(1-10)，回 `OK` / `ERR:RANGE` / `ERR:FORMAT`。

## 引脚 / 接线速查

| 功能 | 真板引脚 |
|---|---|
| USART1_TX | **PA9**（AF7） |
| USART1_RX | **PA10**（AF7） |
| LED 调光 | **PA0**（TIM2_CH1, AF1） |
| 波特率 | 115200-8-N-1，**必须共地** |

> 仿真版用 UART4 + PD14 普通输出；真板换 USART1 + PWM。

## 核心逻辑伪代码

```
parse_num(s,&ok):  # 手写，不用 atoi
    if *s==0: return 0
    while *s:
        if 非数字: return 0        # ok 保持 0
        n = n*10 + (*s-'0'); ok=1
    return n

handle_line(line):
    if 前缀"SETLED:":
        n = parse_num(line+7,&ok)
        if !ok: "ERR:FORMAT"        elif n>255: "ERR:RANGE"
        else: duty = n*1000/256;    "OK"
    elif 前缀"FLASH:":
        n = parse_num(line+6,&ok)
        if !ok: "ERR:FORMAT"        elif n<1 or n>10: "ERR:RANGE"
        else: flash_left = n*2; next_toggle = millis()+200;  "OK"   # ← 不等！
    else: "ERR:FORMAT"

循环:                                  # 收和闪两不耽误
    if RXNE: c = DR; \r或\n→ 处理整行; 否则入 line[]（超长丢弃但不重置 idx）
    if flash_left>0 and millis()>=next_toggle: 翻转, flash_left--, next_toggle+=200
```

## 关键常量

| 项 | 值 |
|---|---|
| 闪烁半周期 | **200ms**（亮200+暗200 = 400ms） |
| **闪一次 = 翻 2 次** | `flash_left = n * 2` ← 最易错 |
| 波特率 | BRR = 84e6/115200 = **729**（误差 0.02%） |
| LED 亮度 | `duty = n * 1000 / 256` |
| 硬件定时器 | **TIM6** 更新中断做 1ms 时基（非 SysTick） |

## 高频追问 + 一句话答法

- **为什么 LED 用 PWM 不用 GPIO？** → SETLED 的 X 有 0~255 共 256 级，GPIO 只能两档，X=1 和 X=255 没区别，浪费量化信息。PWM 后 `duty=X/256`，越大越亮。
- **⚠️ 为什么不用 SysTick？** → SysTick 本质也是硬件定时器，但题目特意强调"硬件定时器"，我用 TIM6（APB1 外设定时器）讲解时没有歧义，且全工程时基统一。
- **400ms 怎么实现？为什么不用 delay？** → delay 会让 CPU 空转、期间收不到新命令，题目要求不得卡死。我用毫秒计数记"下次翻转时刻"，只判断到没到点，到了翻一下就走。
- **闪一次为什么要翻两次？** → 闪一次是"亮"+"灭"两个状态切换，只翻一次灯只会闪一下就没了。FLASH:3 → 翻 6 次。
- **为什么不用 atoi？** → 题目要求；而且 atoi 分不清"abc"（失败）和"0"（合法零），都返回 0。我手写 parse_num 用 `ok` 出参区分。
- **怎么保证连续下发不卡死？** → ①RXNE 轮询不阻塞；②超长丢弃但保留已收的半截；③闪灯期间主循环照样收新命令。

## 被问住就说

> ⚠️ **仿真版 BRR=0x682 是照范本抄的，不是按公式算的真值**（仿真后端不校验波特率）。被问 BRR 怎么算，**只讲真板版**：`BRR = PCLK/波特率 = 84e6/115200 = 729`。
> ⚠️ 仿真版 SysTick 配 168000，Q6/Q8/Q10 配 72000——仿真虚拟时钟不统一，**只影响绝对时间不影响逻辑**；真板统一按 168MHz。
